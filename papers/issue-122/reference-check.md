# Citation report - issue #122

Companion to `manuscript.md`. Two duties: (i) authenticity of every reference, and (ii) coverage
and ambiguity of the in-text citation keys. This report is a declaration; reviewers verify
independently.

## (i) Authenticity - how each entry was verified

**Method.** Every entry is verified by re-fetching it **by its own identifier** and comparing the
returned title against the title recorded at curation time, after normalisation (NFKC, case,
punctuation and whitespace folded). The tool is committed and re-runnable from this directory:

```
python3 refs_tool.py verify     # writes refs/verify.log
python3 refs_tool.py plant      # two-sided control: a corrupted title, an invented id, an invented DOI
```

- **DOI entries** (0) are fetched from `https://api.crossref.org/works/<doi>`.
- **arXiv entries** (102) are fetched from the arXiv API. **Transport note (measured):** this
  endpoint is intermittently unanswered from the authoring host -- the read times out rather than
  returning an error -- so the verifier is cache-first (`refs/verify_cache/`) and a re-run over a
  populated cache is instant and offline. The *metadata* pass (`refs_meta.py`) is where the
  authors come from, and its route on the committed run is stated rather than assumed: the arXiv API answered in **batch** for all 102 ids on the committed run (`route: API batch` in `refs/meta.json`), so no per-id fallback was needed.
- **The route cannot decide the invariant.** The title and author invariants are enforced **where the two routes merge**, not inside either limb, so which route answers cannot decide whether an entry is allowed to carry no authors (`refs_meta.py plant` injects that fault).
- **Title comparison is taken through the XML parser, not a regex over raw text.** Measured on
  2026-10-03: a regex read left XML entity references literal (`&amp;`), which turned one correct
  citation into a false `MISMATCH`. The instrument now parses the Atom feed.
- **A two-sided control is run** (`refs_tool.py plant`): a corrupted title, an invented arXiv id
  and an invented DOI are injected into a throwaway copy of the curated set and **all three must
  fail**; the control asserts its own healthy rows still resolve beside them.

**Result: 102/102 entries resolved to their recorded title, 0 unresolved.** The committed run log
`refs/verify.log` holds **102 `OK` lines and 0 `PROBLEM` lines**; the verification command exits
non-zero if any entry fails, so the verdict is a check rather than a statement.

**Provenance of the curated set.** Each record carries a `source` field naming where its
identifier and title came from: 102 `discovery`. A title read out of the discovery artefact is copied, not
retyped -- which is the property the scan can certify, and the reason a title written from
recollection cannot enter the list unnoticed.

**Author fields.** A verified identifier is not a verified citation record: the identifier pass
above confirms *title identity*, and says nothing about the authors a reference list needs.
Author names and years are fetched in a second pass (102/102 entries carry authors; 0 via Crossref,
102 via the API batch route, as recorded in `refs/meta.json`) and every name in the list is rendered
from `refs/meta.json` --
none is typed. The reference list is generated by `make_references.py` and injected by
`build_manuscript.py`, so the rendered entry and the fetched record cannot drift apart.
The identifier pass proves title identity; the year and category fields come from the same
discovery artefact as the titles and are **not** independently re-verified here.

  before it is `## Figures`. Entries are numbered `[1]`-`[102]` and each begins on its own line,
  separated by a blank line, so the list is read as a list rather than as one paragraph.
- **Coverage**: 102 entries, **102 cited in the body text by their numbered key**, 0 uncited.
  Every in-text citation is a bracketed number; no work is cited by name or by bare arXiv id
  without its key.
- **Uncited entries**: none.
- **Bracketed groups, by class** (a computed scan, not an assertion): 97 in the body -- **86**
  are citation keys (digit lists whose every number is a numbered entry), **0** are digit lists
  that do NOT resolve -- the shape-ambiguous class, which must be empty -- and **11** are not
  digit lists at all (inline mathematics and figure cross-references: `[ℓ(q)]`, `[q_{t+1}]`, `[q_t]`, `[ℓ_i(q)]`, `[q]`, `[Figure 1]`).
  None is a data literal in the citation shape; the two conventions are kept apart in the
  text, and a violation of that would appear in this line rather than in the count.
- **Window the gate reads**: the last `## References` heading to the end of the file. The 102
  numbered lines it holds are the entries themselves, nothing else numbered follows them, and the
  section before it is `## Figures`, so the window and the bibliography section coincide.

bibliography number entries `[n]`, so a counter keyed on `[n]` reads the same 102 entries the
block holds — there is no second marker form for the gate to pair against. The gate printed
**0** advisory line(s) on this manuscript. The counts that matter are the ones printed in
the block above, at the revision the block names. (102 entries; 102 cited in the body; 0 uncited.)
