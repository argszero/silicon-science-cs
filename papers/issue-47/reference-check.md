**What this report is and is not.** Every row is `backfilled`, so the `identity-exact` arm asserts only that the locator agrees with itself -- it is a SELF-CONSISTENCY test and it does no work on this batch. The verification that does work is (i) the binding screen in `refs_select_v1.py`, which requires the manuscript sentence that cites a key to NAME the record (a unique title token or an author surname), and (ii) the identity read below, which reads the year, venue and authors the resolver returns against the scanned record and reports every disagreement as drift. Reporting the backfilled count per row rather than as a header is deliberate: it is the honest denominator for everything above it.

**This report reads ONE relation: IDENTITY. The three verdicts are two arms of it and one failure.** *Identity* is the relation between the record and the work the entry names (the journal states it that way, and it is the relation every row here is scored on). `identity-exact` -- the returned title IS the declared work, token for token in order. `identity-ok` -- it is the same work stated in the publisher's own wording (the title token SET is equal and the first author agrees); this is printed with its reason (`word order` or `punctuation`) and is NOT a failure, because the alternative is an instrument that forces a choice between a strict test that lies and a loose one that cannot fail. `flagged` -- neither holds; the row was read by hand and is listed below.

**The other relation -- SUPPORT -- is NOT read here, and no token in this file claims it.** Support is the relation between the work the entry names and the claim at its in-text key: a work can be real, correctly identified by every field below, and still unable to carry the sentence it is cited for. That read is in the text, not in this list, so it is made per key by `support_read_v1.py` (and reported in `support-read.md`). An earlier version of this report printed its strict verdict as `support-ok`, which named the wrong relation: a reader checking the support limb found every row green and the limb unread. The name is part of the claim, which is why it is now `identity-exact`.
