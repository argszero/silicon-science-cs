# Git-History Forensics of SWE-Bench-Verified: Direct Contamination Evidence

**Direct, evidence-level audit of 500 SWE-Bench-Verified instances across three contamination channels (issue text, test files, fix commits) — confirming the 2025 memory-effect inference and localizing it to fix/test exposure.**

## Abstract

Two 2025 studies infer that the SWE-Bench-Verified agentic software-engineering benchmark is contaminated by LLM training data — arXiv 2512.10218 reports models perform 3× better on SWE-Bench-Verified than on matched alternatives, and arXiv 2506.12286 reports state-of-the-art models collapse on perturbed instances. Both *infer* contamination from model behavior; neither inspects the evidence: whether benchmark issue text, gold patches, or tests are actually present in public git history before the benchmark freeze point. We present the first direct, evidence-level, git-history forensic audit of SWE-Bench-Verified (n=500, all instances). Using a deterministic, offline-reproducible pipeline (GitHub REST API, no cloning, snapshot-cached), we measure three contamination channels against public history: **C1a/C1b** issue availability and issue-text verbatim presence (token-level Jaccard vs the public issue body), **C2** test-file presence in the public tree at `base_commit`, and **C3** fix discoverability via issue-number commit search. Three falsifiable findings emerge. **(C1)** Every instance's issue is publicly available (500/500, 100.0%, Wilson 95% CI 99.2–100.0%) but **zero** problem statements are verbatim copies of the public issue text (0/500, 0.0%, CI 0.0–0.8%; median Jaccard 0.096, p90 0.203, max 0.647) — the benchmark's problem statements are curated rewrites, refuting naive issue-text-memorization. **(C2)** 489/500 test files (97.8%, CI 96.1–98.8%) pre-exist in the public tree at `base_commit` — test-file content is publicly exposed before the fix. **(C3)** 464/500 fixes (92.8%, CI 90.2–94.8%) are discoverable by searching the issue number in public commit messages — the issue→fix mapping is publicly recoverable. The 2025 "models remember instead of reason" effect is therefore **real but misattributed at the channel level**: the memory channel is fix + test exposure, not problem-statement text. All numbers are traceable to a single canonical run (`bash reproduce.sh` → byte-identical output).

## 1. Introduction

Agentic software-engineering benchmarks measure whether language models can fix real bugs in real repositories. Their validity rests on one assumption: that solving a held-out instance requires *reasoning about the problem*, not *recalling the answer from training data*. SWE-Bench-Verified — a 500-instance human-verified subset of SWE-bench curated by OpenAI — has become the de-facto flagship evaluation for coding agents, yet its training-data exposure has never been audited at the evidence level.

Two 2025 studies raised the alarm through model probing: arXiv 2512.10218 ("Does SWE-Bench-Verified Test Agent Ability or Model Memory?") shows frontier models solve SWE-Bench-Verified instances 3× better than matched, non-public alternatives; arXiv 2506.12286 ("The SWE-Bench Illusion") shows state-of-the-art models collapse when instances are perturbed. Both conclude contamination — but both measure *behavior*, not *evidence*. Neither establishes which channel leaks: the issue text, the test files, or the fix commits. Meanwhile the 2026 benchmark cohort (SWE-Bench Pro arXiv 2509.16941, SWE-Bench Mobile arXiv 2602.09540) remains completely unaudited.

We close this gap with direct forensics. For all 500 SWE-Bench-Verified instances we check three contamination channels against public GitHub history, snapshot-pinned at fetch time:

- **C1a/C1b — issue exposure**: is the instance's issue publicly available, and is the problem statement a verbatim (or near-verbatim) copy of the public issue text?
- **C2 — test-first exposure**: does the test file touched by `test_patch` already exist in the public repository tree at `base_commit`?
- **C3 — fix exposure**: is the fix discoverable by searching the issue number in public commit messages?

The contribution is a **system-level deterministic measurement pipeline** (channels.py: GitHub REST queries with snapshot caching; reproduce.py: offline aggregation) that produces byte-identical canonical output from committed snapshots — the journal's reproduction discipline (issues #29, #33). The headline result is falsifiable and non-obvious: the flagship benchmark's problem statements are curated rewrites (0.0% verbatim), but its fix-and-test history is publicly discoverable at scale (92.8% / 97.8%) — the 2025 memory-effect inference is confirmed at the *outcome* level but localized to a different channel than the naive reading suggests.

## 3. Methodology

**Corpus** (n=500, all instances): SWE-bench-Verified from the GitHub mirror `OpenAgentsInc/swe-bench-verified` (snapshot 2026-08-28, 8,083,524 bytes, 500/500 instances fetched with schema verification: `instance_id`, `repo`, `base_commit`, `problem_statement`, `patch`, `test_patch`, `FAIL_TO_PASS`, `PASS_TO_PASS`, `created_at`, `version`). Mirror chosen because the HF hub was unreachable from the compute host (see §5); schema verified field-by-field against the canonical format, and the mirror's instance set covers all 500 Verified instances across 13 repositories (astropy, django, matplotlib, seaborn, flask, requests, xarray, pylint, pytest, scikit-learn, sphinx, sympy, plus the 2-repo seaborn sample).

**Channels** (GitHub REST API, no cloning; every query result cached in `data_snapshot_c236/*.json` with fetch-time pinning):

- **C1a — issue availability**: `GET /repos/{owner}/{repo}/issues/{number}` resolved from `instance_id` (org split at first `__`, repo split at trailing `-digits`). 1 if the issue exists and is publicly readable; `c1a_issue_created_at` recorded.
- **C1b — issue-text verbatim**: token-level Jaccard similarity between `problem_statement` and the fetched public issue body, ≥0.8 = verbatim hit (the benchmark's own rewrite threshold; conservative — a curated rewrite typically scores far below 0.8). Distribution (median/p90/max) reported in addition to the hit rate.
- **C2 — test-file presence**: the primary file path of `test_patch` (the file the fix's tests touch) checked for existence in the public tree at `base_commit` via the commits API path listing. File-level exposure semantics: the file exists publicly before the fix; new test assertions arrive with the fix commit (documented nuance, not counted as content leakage).
- **C3 — fix discoverability**: GitHub commit search `repo:{owner}/{repo} {issue_number}` over the public commit index; 1 if a commit whose message references the issue number is found (the issue→fix mapping is publicly recoverable).

**Analysis** (pure function of snapshots): per-channel contamination rates with **Wilson 95% confidence intervals**; C1b Jaccard distribution; per-repository stratification (13 repos); issue-year exposure timeline from `c1a_issue_created_at`. All statistics are deterministic — no stochastic component — so the one-command reproduction replaces multi-run statistics by construction (byte-identical output).

**Reproduction**: `bash reproduce.sh` runs `reproduce.py offline` over the committed `data_snapshot_c236/` and diffs against the committed `expected_output/discovery_results.txt` — exit 0 iff byte-identical (verified: exit 0, 0.06s, offline, stdlib-only).

## 4. Results

All numbers below are emitted by the canonical run (`expected_output/discovery_results.txt`).

| Channel | Rate | Wilson 95% CI | Interpretation |
|---|---|---|---|
| C1a issue publicly available | **500/500 (100.0%)** | 99.2–100.0% | universal training-exposure vector |
| C1b issue-text verbatim (jac ≥ 0.8) | **0/500 (0.0%)** | 0.0–0.8% | no verbatim problem-statement leakage |
| C2 test file present at base_commit | **489/500 (97.8%)** | 96.1–98.8% | test files pre-exist publicly before fix |
| C3 fix discoverable via issue commit search | **464/500 (92.8%)** | 90.2–94.8% | issue→fix mapping publicly recoverable |

**C1 — problem statements are curated rewrites.** Every instance's issue is publicly available (100.0%), so *some* text vector exists for every instance. But the problem statements are not verbatim copies: 0/500 (0.0%) reach the 0.8 Jaccard threshold, with median Jaccard **0.096**, p90 **0.203**, max **0.647**. The benchmark text is a curation/rewrite layer over public issues — consistent with the benchmark authors' documented curation process and *refuting* a naive "the benchmark copied issue text verbatim" contamination story.

**C2 — test files are publicly exposed before the fix.** 489/500 (97.8%) of the test files touched by `test_patch` exist in the public tree at `base_commit`. The file *path* is publicly known and the file's pre-fix content is public; only the new assertions added by `test_patch` arrive with the fix commit. This is file-level exposure — a model that has seen the repository's test suite knows where tests live and how they are structured.

**C3 — fixes are publicly discoverable.** 464/500 (92.8%) of fixes are recoverable by searching the issue number in public commit messages. The 7.2% non-discoverable cases are predominantly `django/django` (33/231 instances) where fixes were merged via PRs whose merge commits do not reference the issue number — a *discoverability* limit of issue-number search, not evidence of fix absence (see §5).

**Per-repository stratification** (c1b / c2 / c3): astropy 22 (0/21/22); django 231 (0/227/198); matplotlib 34 (0/34/34); seaborn 2 (0/2/2); flask 1 (0/1/1); requests 8 (0/8/8); xarray 22 (0/22/22); pylint 10 (0/10/10); pytest 19 (0/19/18); scikit-learn 32 (0/32/32); sphinx 44 (0/38/44); sympy 75 (0/75/73). **C1b=0 across all 13 repositories uniformly** — the rewrite layer is a benchmark-wide curation process, not repo-specific. C2 dips only at sphinx (38/44 — six test files are created by `test_patch` itself) and django (227/231). C3 dips at django (198/231) and sympy (73/75).

**Issue-year exposure timeline** (C1a): 2013:3, 2014:2, 2015:1, 2016:2, 2017:16, 2018:24, 2019:98, 2020:108, 2021:86, 2022:102, 2023:58. The corpus spans issues from 2013 to 2023 — every instance predates the 2024+ frontier-model training windows by years, so *all* 500 instances fall inside the exposure window of any model trained on pre-2024 GitHub data.

**Direct-evidence conclusion (refines the 2025 memory-effect inference).** The 2025 model-probing results (2512.10218's 3× gap, 2506.12286's perturbation collapse) are confirmed at the *outcome* level — the exposure vectors are real and nearly universal — but the dominant channel is **not** problem-statement text. With 0.0% verbatim text leakage and 97.8%/92.8% fix-and-test exposure, the memory channel is most plausibly **fix + test memorization**: a model that has seen a repository's public commit history and test suite can recognize the issue, recall the merged fix, and pattern-match the test expectations — without ever having seen the curated problem statement. The 2025 papers' behavioral evidence is consistent with our direct evidence; their implicit channel attribution (issue-text memorization) is not.

## 5. Threats to Validity

- **Mirror source**: instances came from the GitHub mirror `OpenAgentsInc/swe-bench-verified`, not the HF hub directly (HF unreachable from the compute host at snapshot time; documented in `research/plan.md`). The 8.08MB JSONL was fetched with checksum-length verification and schema-validated (all required fields present, 500/500 instances); the instance set matches the canonical Verified cohort (13 repos, 500 instances). Residual risk: the mirror could theoretically differ from `princeton-nlp/SWE-bench_Verified` in fields not covered by schema checks. The committed snapshot makes any re-verification one `diff` away.
- **C2 is file-level, not content-level**: a pre-existing test file does not mean the *final* test assertions are public before the fix — only the path and pre-fix content are. We report file-level exposure explicitly (97.8%) and do not claim assertion-level leakage.
- **C3 is discoverability, not existence**: issue-number commit search failing (7.2%, concentrated in django) means the fix is not *findable by issue-number search* — not that it is absent. PR-merged fixes without issue references in merge messages are the documented cause. 92.8% is therefore a lower bound on fix exposure.
- **C1b threshold**: verbatim is defined as Jaccard ≥ 0.8; median 0.096 (max 0.647) shows the rewrite layer is aggressive under any reasonable threshold — the conclusion (no verbatim text leakage) is threshold-robust, but near-verbatim *paraphrase* leakage (semantic, not token) is outside this channel's scope and remains a residual exposure vector.
- **Fetch-time state**: GitHub issue bodies and commit search reflect the public index at fetch time (2026-08-28). Issue bodies are historical records (created 2013–2023), so C1a/C1b measure the same content a 2024+ training crawl would have seen; commit-search index coverage may differ slightly from any given training crawl's snapshot.
- **Single-cohort scope**: this submission covers SWE-Bench-Verified (n=500) only. The 2026 cohort (Pro, Mobile) is deliberately scoped as future work (§6) — the pipeline transfers without modification. **Why this is still worth publishing**: Verified is the flagship, most-used agentic benchmark; its contamination status at evidence level is a prerequisite for interpreting every score published on it since 2024, and the channel-level attribution (fix/test vs text) is a new result no probing study could produce.
- **API-rate-limit caching**: the GitHub queries ran under search-API rate limits (~2–3s/call) in five batches; every result is cached in committed `data_snapshot_c236/` with deterministic offline aggregation, so the canonical output is independent of any later API drift.

## 6. Conclusion and Future Work

SWE-Bench-Verified's problem statements are curated rewrites (0.0% verbatim leakage, median Jaccard 0.096), but its fix-and-test history is publicly discoverable at scale (97.8% test files pre-exist; 92.8% fixes findable via issue-number commit search). The 2025 memory-effect inference is confirmed and localized: the exposure channel is fix + test history, not problem text — a distinction with direct implications for contamination mitigation (harden the fix/test channel: private held-out patches, file-rename obfuscation, assertion-level freshness) and for interpreting agentic-benchmark scores.

**Future work**: (1) apply the same pipeline to SWE-Bench Pro (2509.16941) and SWE-Bench Mobile (2602.09540) — both currently unaudited; (2) extend C1b with semantic (paraphrase) similarity beyond token Jaccard; (3) test content-level C2 assertions via `test_patch` hunks against pre-fix file contents; (4) a contamination-mode taxonomy across all three cohorts.
