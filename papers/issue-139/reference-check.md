# Reference check -- issue #139

**What this file is.** The verification report for the reference layer of issue #139 (*Proving Is Not
Paying: the Success-vs-Cost Frontier of Interdependent Proof Obligations*). Every entry in the pool was
discovered by `refscan139.py` -- nothing is typed from memory -- and each was checked against a **live
external record** by comparing the returned **title** with the stored title, two-sided (the score is
the *smaller* of the two coverage fractions, so a short generic title cannot reach 1.00 against a long
specific one).

**Result: 288 / 288 VERIFIED, 0 title mismatch, 0 transport-unknown.** The pool holds **288** entries
(277 arXiv, 11 Crossref), well above the journal's 100-reference floor, and **all 288 are cited in the
manuscript** -- the gate's coverage reads 100.0%, so there is no padding entry and no uncited one. The
full per-entry table is `reference-pool.md`; the machine-readable pool is `refs/pool.json`; the
role classes the citation list is scoped by are `refs/roles.json`.

## Method

| Source | Use | Endpoint |
|---|---|---|
| arXiv API | discovery | `search_query=<topic>` -- 45 queries derived from this paper's own subject (proof obligations, proof/verification cost and budget, proof search and scheduling, proof assistants and SMT, LLM and agentic theorem proving, benchmarks and evaluation, dependent/adaptive search theory) |
| arXiv API | verification | `id_list=<ids>` in batches of 20, `max_results` set to the batch size and the returned count asserted (the endpoint caps a request at 10 titles unless told otherwise -- a truncation disguised as a data problem) |
| Crossref | canonical works, found **BY TITLE** | `query.bibliographic=<title>` |
| Crossref | verification | `works/<doi>` |

**Why a title match and not the HTTP status.** A DOI or an arXiv id written from memory *resolves*:
the endpoint returns 200 with a **real** record -- of a **different** paper. So the check is the
returned title against the stored title, scored two-sided. Threshold **0.80**. Every canonical work is
found **by title**, never by a remembered identifier.

**Transport failures are not findings.** An API outage yields `TRANSPORT-UNKNOWN`, never "these records
do not exist", and fails the run. The final pass is `0`.

**How the pool was curated (and why the threshold is a property of the vocabulary).** Discovery
returned 1809 raw candidates; curation kept 288. The filter is `core_hits >= 2 AND supporting_hits >= 4`
on the query terms, which is a *stricter* rule than the one used for a sibling paper on a
high-entropy subject, and the reason is stated here because it is a finding: on low-entropy domain
vocabulary (this paper's "formal verification", "proof obligation", "proof search") a weaker rule lets
most of the raw scan through, because every document in the field contains the words. A curation
threshold is calibrated against the **vocabulary it reads**, not against a pipeline in general.

## Defects found and repaired while building this layer

1. **One canonical work with no real record.** The prospectively canonical entry *The Cost of Formal
   Verification* was dropped: Crossref returned no record under that title (`query.bibliographic`, and
   by exact `query.title`), and the best discovery match against any real paper scored 0.60 -- i.e. the
   only ways to keep it were a fabricated identifier or a weak match against someone else's work. An
   unverifiable citation cannot be cited, so the entry was removed, not admitted. **This is the
   distinction the check exists to make**: a memorable title is not a record.
2. **A curation threshold inherited from a different vocabulary.** Re-using the sibling paper's
   `core >= 1 or support >= 4` rule passed 1407 of the 1630 candidates through, because this paper's
   terms are low-entropy domain words that appear in most of the field's abstracts and titles. The rule
   was tightened to `core >= 2 and support >= 4`, giving 288 -- and the tightening is stated here
   because a curation threshold is a property of the vocabulary it reads.
3. **One paper, two records.** Where a work arrives both as an arXiv preprint and as a published record,
   the pool keeps **one** entry; the offline gate asserts the pool has no duplicate title, so a single
   paper cannot be cited as two references.
