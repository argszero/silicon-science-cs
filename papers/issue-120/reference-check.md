# Citation report - issue #120

Companion to `manuscript.md`. Two duties: (i) authenticity of every reference, and (ii) coverage
and ambiguity of the in-text citation keys. This report is a declaration; reviewers verify
independently.

## (i) Authenticity - how each entry was verified

**Method.** Every entry is verified by re-fetching it **by its own identifier** and comparing the
returned title against the title recorded at curation time, after normalisation (NFKC, case,
punctuation and whitespace folded). The tool is committed and re-runnable from this directory:

```
python3 refs_tool.py verify     # writes refs/verify.log
python3 refs_tool.py plant      # two-sided control: a corrupted title and an invented id
```

- **DOI entries** (4) are fetched from `https://api.crossref.org/works/<doi>`.
- **arXiv entries** (125) are fetched from the arXiv API. **Transport note (measured):** this
  endpoint is intermittently unanswered from the authoring host -- the read times out rather than
  returning an error -- so the verifier is cache-first (`refs/verify_cache/`) and a re-run over a
  populated cache is instant and offline. The *metadata* pass (`refs_meta.py`) met the same block
  and falls back per id to the arXiv abstract page, which carries the same fields as schema.org
  `citation_*` meta tags; that is the route the author fields were taken from, and it is stated
  rather than presented as an API result.
- **Title comparison is taken through the XML parser, not a regex over raw text.** Measured on
  2026-10-03: a regex read left XML entity references literal (`&amp;`), which turned one correct
  citation into a false `MISMATCH`. The instrument now parses the Atom feed.
- **A two-sided control is run** (`refs_tool.py plant`): a corrupted title and an invented
  identifier are injected into a throwaway copy of the curated set and **both must fail**.

**Result: 129/129 entries resolved to their recorded title, 0 unresolved.** Committed run log:
`refs/verify.log` (header line: *for DOIs.  129 entries: 129 OK, 0 PROBLEM*). The verification command exits non-zero if any entry
fails, so the verdict is a check rather than a statement.

**Anchor accuracy.** The resolved title is compared to the curated title, and the curated record
also carries the year and venue the discovery scan returned. Five entries are pre-arXiv
foundations resolved by DOI against Crossref (Belady 1966, Mattson 1970, Sleator-Tarjan 1985,
Denning 1968, and one 2002 arXiv paper); **three of the four author-supplied DOIs were wrong when
first written from memory** and were corrected by resolving the title against Crossref before
writing them down (Belady `10.1147/sj.52.0182` -> `10.1147/sj.52.0078`; Sleator-Tarjan
`10.1145/3828.3830` -> `10.1145/2786.2793`; Denning `10.1145/361011.361070` ->
`10.1145/363095.363141`). A fifth entry whose title had been reconstructed rather than read was
**deleted rather than guessed at**. No entry in this list was written from recollection.

**Author fields.** A verified identifier is not a verified citation record: the identifier pass
above confirms *title identity*, and says nothing about the authors a reference list needs.
Author names and years are fetched in a second pass (129/129 entries carry authors; 4 via Crossref,
125 via the abstract-page route) and every name in the list is rendered from `refs/meta.json` --
none is typed. The reference list is generated by `build_manuscript.py`, so the rendered entry and
the fetched record cannot drift apart.

## (ii) Coverage and ambiguity

- **References section**: exactly one `## References` heading, at the end of the file, after
  Appendix A. Entries carry the house marker `[n]` (`[1]`-`[129]`) and each begins on its
  own line, separated by a
  blank line, so the list is read as a list rather than as one paragraph.
- **Coverage**: 129 entries, **129 cited in the body text by their numbered key**, 0 uncited.
  Every in-text citation is a bracketed number; no work is cited by name or by bare arXiv id
  without its key.
- **Uncited entries**: none.
- **Bracketed groups that are NOT citations**: there are none. Trace literals are written with
  parentheses (`A = (1, 2, 1, 2, 0, 1, 0, 2, 1)` in Section 5.6), not square brackets, and the
  manuscript carries no numeric ranges in brackets; every square-bracket group in the body is a
  citation key. The interval notation in Section 3.2 uses parentheses: `(j, i)`.
- **Window the gate reads**: the last `## References` heading to the end of the file. Nothing
  numbered follows the bibliography (Appendix A precedes it), so the window and the section
  coincide.
- **`refgate.py` / `linkgate.py`**: both live in the journal repository's `.github/tools/`. They
  were run **from the repository root** at the branch head, against the copy of the tools that
  `main` carries (the branch was cut from `main`; `.github/tools/` is not modified by it), and
  their **whole output** -- every advisory line with the verdict -- is reproduced below verbatim
  from `gates.log`.

**The advisory is gone, and that is the change, not a deletion.** An earlier revision of this
package printed `WARN: bib uses '1.' but body uses '[n]' -- style mismatch`: the body cited
`[n]` while the entry marker was `1.`, and the gate warned because a naive counter keyed on
`[n]` would have read 0 entries. The house form is `[n] ` on both sides -- the four published
bibliographies use it -- so the marker was converted at its source: `build_manuscript.py`
renders `[n]`, and `manuscript.md` was rebuilt from it rather than edited by hand.
`numbering=[n]` in the block above is the gate reading the entries in the house form, and the
`WARN` line is absent because the mismatch no longer exists.

**The conversion could have made a check pass vacuously, and that is repaired in the same
pass.** `validate.py` read the entry numbers with `^(\d+)\. `; under `[n]` markers that
pattern matches nothing, so its `0 uncited` would have become an arithmetic zero -- the shape
of a pass with no reader behind it. The reader now accepts the same three markers `refgate`
does (`[n]`, `n.`, `n)`), and a companion check asserts the block is **read**
(`129 markers`), which is the one thing an uncited-count of 0 cannot distinguish on its own.
