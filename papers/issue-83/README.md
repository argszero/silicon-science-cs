# Issue #83 — Can a Destroyed Search Channel Be Restored? (RLVR entropy-collapse recovery)

**Contribution level: `theory+empirics`** — controlled interventions across two collapse
regimes (DESTROY add-carry, GREEDY-BLIND parity), 3-seed statistics at a fixed held-out
evaluation seed, exact ground truth, matched-budget baselines (policy-space pressure vs
data reintroduction, fresh-from-scratch warm-start control), and falsifiable registered
priors reported including one refutation.

## Abstract (for the PR)

Outcome-only verifiable-reward RL can destroy a policy's sampling support: the DESTROY
regime collapses pass@k while greedy recovers, and every existing remedy is a
*prevention* method applied during training. From the fully observable 1.8M-parameter
toy system of issue #79 we collapse policies by construction (add-carry c=0.01, parity
c=0.10, 1500-step GRPO) and apply candidate recovery interventions from the same
collapsed checkpoint. **Policy-space pressure does not recover the channel**: continued
outcome-only RL, KL re-anchoring to the SFT base (β up to 100× canonical), and entropy
bonuses leave pass@64 at 0.10–0.33 (base 0.79–0.88) or destroy the answer format.
**Data reintroduction does**: SFT-replay on the base's coverage data restores pass@64 to
≥ the seed's own base in 3/3 seeds within one base-training budget (s0 0.146→0.938,
s1 0.208→0.854, s2 0.062→0.438), re-expanding per-prompt answer entropy 0.50→2.66 bits.
Registered prior P1′ (collapse is an absorbing state) is **refuted**; P1 is confirmed in
refined form — recovery requires reintroducing the base's *data distribution*, not
policy-space reference pressure. GREEDY-BLIND separates the mechanisms: replay restores
the RL-destroyed 2-value channel (odd pass@64 0.02→0.94) while the SFT-imbalance-pinned
argmax stays 0.000. And the "destroyed" policy is the best warm start:
replay-from-collapsed @300 steps (0.729) where fresh training cannot even bootstrap the
class (0.000). Decision: RLVR practitioners should keep collapsed checkpoints and plan
data replay as the recovery path; prevention methods (KL/entropy) are not cures; greedy
metrics cannot see collapse or recovery.

## One-command reproduction

    bash reproduce.sh

- Truly one command **from a fresh clone**: bootstraps `.venv` (torch 2.9.1; network
  once), trains the c=0.01 SFT base (600 steps), collapses it with 1500-step KL-anchored
  GRPO (the issue #79 DESTROY recipe), runs the recovery arms from the same collapsed
  checkpoint (continue 500 / KL-re-anchor β=0.01 500 / KL-re-anchor β=1.0 500 /
  SFT-replay 600), and evaluates greedy (n=384) + pass@64 (n=48) at held-out seed 777.
- Runs `validate.py` with the **two-tier scheme** of manuscript §8:
  - **Tier A — structural cells**: the collapsed state's DESTROY signature, asserted
    relative to the same run's base (collapsed greedy within 0.1 of base greedy while
    collapsed pass@64 ≤ base pass@64 − 0.4).
  - **Tier B — mechanism cells**: SFT-replay pass@64 ≥ base pass@64 after 600 steps and
    ≥ 2× the collapsed value; every policy-space arm (continue, KL-re-anchor β=0.01/1.0)
    stays < base − 0.3.
  - Expected output: all checks passed; exit 0. Exact stochastic values are reported
    per run (README_repro.md), not asserted to ±0.03 (per the issue #79 R179 lesson:
    run-to-run spread ~±0.1 at this scale).
- Runtime: ~20–40 min on 10 CPU cores (measured 17 min). CPU-only, no GPU; MPS not
  used for canonical runs (seed-pinned CPU repro identity).

## Registered prior-belief reconciliation (see manuscript §2)

P1 (entropy-restoring interventions recover within ≤ 2× prevention budget) confirmed in
refined form — data replay recovers, policy-space pressure does not; P2 (hysteresis)
reframed by the warm-start result (cure ≤ re-prevention cost and lands higher when the
base was not kept); **P1′ (absorbing state) refuted 3/3** — the registered
strong-novelty refutable variant.
